# Galbox 用户手册

本手册的每一步都对照真实界面与代码写成：界面文字取自 XAML，行为取自对应的 ViewModel。
**凡是没有界面入口的功能，这里会直接说"做不了"，而不是给你一套点不出来的步骤。**

> 适用范围：`merge/all-features` 分支（提交 `0e051ea`）之后的构建。
> 早期文档 `docs/USER_MANUAL.md` 描述的部分功能（补丁下载、卸载补丁等）在当前代码中并不存在。

## 1. 启动与界面地图

双击 `Galbox.App.exe`（或 `dotnet run` 构建产物）后，主窗口左侧是导航栏，共有 6 个入口
（`src/Galbox.App/MainWindow.xaml`）：

| 菜单 | 里面是什么 |
|---|---|
| **主页** | 快速启动最近玩过的游戏、正在游玩 / 收藏 / 最近游玩三排缩略图、空库时的引导 |
| **游戏库** | 游戏列表（网格视图 / 表格视图）、搜索、筛选、排序、添加与批量扫描 |
| **存档管理** | 按游戏管理存档备份：创建、恢复、快速切换、删除；另外是**存档节点**：扫描存档 → 时间线、CG 图鉴、剧情进度、快照标记 |
| **补丁中心** | 上面是数据库里的补丁记录（当前通常是空状态，原因见第 8 节）；下面是**「本地补丁包（已下载）」**：预览 → 安装 → 回滚 → 状态台账 → 中断恢复 |
| **刮削进度** | 刮削任务的进度、每个数据源的诊断信息、候选结果与「应用」按钮 |
| **错误报告** | 已记录的问题列表、重新检测、标记已解决、尝试修复 |
| **设置**（导航栏底部，齿轮图标） | 数据源、账号、老板键、截图、路径等 |

**启动失败怎么办**：如果窗口没出现，程序会在弹窗里直接告诉你日志路径，形如
`%LocalAppData%\Galbox\logs\startup-YYYYMMDD.log`（`StartupDiagnostics.ReportStartupFailure`）。
把那个文件的内容发出来，比"双击没反应"有用得多。

## 2. 添加游戏

### 2.1 添加单个游戏（推荐）

1. 打开左侧导航 **游戏库**。
2. 点右上角的 **图标按钮**：那个加号图标（把鼠标停在上面会显示"**添加单个游戏文件夹**"）。
   主页的「添加游戏」按钮也会把你带到游戏库。
3. 在弹出的文件夹选择框里选中**游戏本体所在的那一层目录**（不是上一层），例如
   `D:\GAME\Dreamin'_Her`。
4. 程序会依次做四件事（`LibraryViewModel.AddGameAsync`）：
   * 在该目录里挑主程序（找不到 `.exe` 会提示"文件夹中没有找到可执行文件"，中止添加）；
   * 计算目录大小；
   * 用**文件夹名**当作游戏原名；
   * 按目录特征判断引擎类型，并在成功提示里显示，例如 `已将 'Dreamin'_Her' 添加到游戏库 (引擎: Renpy)`。

   如果这个目录已经在库里，会提示"该游戏文件夹已在游戏库中"。

5. **如果设置里开着"添加游戏后自动刮削"**，添加成功后会**自动跳到「刮削进度」页面**开始刮削
   （`LibraryViewModel.TryStartAutoScrapeAsync` → 导航到 `ScrapingProgress`）。
   没开的话就停在游戏库，之后手动刮削（见第 4 节）。

### 2.2 批量扫描一个总目录

1. 游戏库 → 右上角那个"**批量扫描游戏文件夹**"图标按钮（悬停可看到提示文字）。
2. 选中**所有游戏的外层目录**（例如 `D:\GAME`）。
3. 程序只扫描**下一层子目录**（不递归更深），并且：
   * 子目录里**没有 `.exe`** → 跳过；
   * 找不到可用主程序 → 跳过；
   * 该路径已在库中 → 跳过；
   * 其余逐个加入游戏库。
4. 结束后会给出"新增 N 个、跳过 M 个"的统计（`LibraryViewModel.ScanFolderAsync`）。

> 注意：如果你的游戏目录结构是 `D:\GAME\厂商\游戏名\`，直接扫 `D:\GAME` 会把"厂商"层当成游戏。
> 这种情况请对每个厂商目录分别扫描，或用 2.1 逐个添加。

### 2.3 库页面的常用操作

* **搜索框**：按中文名 / 原名 / 开发商过滤。
* **筛选下拉框**：全部 / 收藏 / 正在游玩 / 已完成 / 从未游玩 / 最近添加。
* **排序下拉框**：添加时间、名称、发布日期、游玩时间、最后游玩、评分等。
* **网格/表格两个切换按钮**：表格视图点列标题（名称 / 添加日期 / 最后游玩 / 游玩时间）可排序。
* **刷新按钮**：重新从数据库载入列表。
* 卡片/行上悬停会出现**快速启动**按钮，直接拉起游戏。

## 3. 游戏详情页

在游戏库里点任意一个游戏即可进入详情页。可用的操作（`GameDetailPage.xaml` / `GameDetailViewModel`）：

| 区域 | 操作 |
|---|---|
| 顶部按钮 | **启动**（用主程序启动，并开始记录本次游玩）、**其他方式**（下拉列出目录里的其它可执行文件，可选一个启动）、**刮削**、**收藏/取消收藏** |
| 简介 | 刮削回来的剧情简介 |
| 角色 | 角色列表，「显示全部角色」展开 |
| 游玩统计 | 游玩时间、启动次数、最后游玩时间、安装目录大小 |
| 文档 | 游戏目录里的文档（点击用系统默认程序打开） |
| 截图 | 从数据库读取的截图缩略图（点击放大）。**当前通常为空**——见下面的说明 |
| 媒体文件 | 游戏目录里的图片/视频等，点击播放 |
| **存档备份** | 「创建备份」按钮，以及每个备份行的「恢复」「删除」 |

「创建备份」会调用真正的存档服务，把检测到的存档文件打包成 ZIP，存放在
`%LocalAppData%\Galbox\SaveBackups\`（`GameDetailViewModel.CreateSaveBackupAsync`）。
如果检测不到任何存档文件，会明确告诉你，而不是假装成功。

## 4. 刮削元数据

### 4.1 手动刮削一整个游戏

1. 进入该游戏的详情页。
2. 点 **刮削**。程序会跳到「刮削进度」页面并自动开始（`GameDetailPage.xaml.cs.OnScrapeClick`
   → 导航到 `ScrapingProgress`，参数是游戏 ID）。
3. 页面从上到下依次显示：
   * 当前处理的游戏、总进度条；
   * 计数：总数 / 已完成 / 成功 / 需复核 / 失败 / 用时 / 预计剩余；
   * 「取消刮削」按钮（运行中才出现）；
   * **数据源诊断**：每个源**实际用的关键词、返回条目数、状态与错误信息**。
     这一栏的意义是让"上游报错"和"确实没这个游戏"能区分开；
   * **候选结果**：按匹配度排序，每条右侧有「应用」按钮。**低于自动接受阈值的结果不会自动写入，
     但仍然可以在这里手动应用**；
   * **本次处理的游戏**：逐游戏的匹配分与状态。
4. 点某条候选右侧的「应用」即可把该条元数据写入这个游戏
   （`ApplyCandidateAsync` → `IAutoScrapingService.ApplyMetadataAsync`），页面顶部会显示
   "已应用「…」到游戏 N"。

### 4.2 自动接受阈值与数据源

在 **设置 → 数据源** 里可以：

* 开关 **Bangumi / VNDB / ymgal / cngal** 四个源；
* 调整 **匹配阈值**（默认 90%）：达到阈值的候选会被自动采用，不必手动点「应用」；
* 调整源的**优先级顺序**（分数相同时按它取舍）；
* 打开 **添加游戏后自动刮削**。

这些设置**是真的生效的**：刮削链路通过 `IScrapingSettingsProvider` 读取它们
（阈值、开关、优先级、自动刮削）。

> **ymgal / cngal 现在是真的能查的**：两个客户端都已接上真实接口，而且**都不需要你申请密钥**
> ——ymgal 用官方文档公开的公共客户端（想换成自己的 client 可以设环境变量
> `GALBOX_YMGAL_CLIENT_ID` / `GALBOX_YMGAL_CLIENT_SECRET`），cngal 的 API 本身无需 key。
> 因此四个源都可以打开。已知的上游小毛病：ymgal 偶发返回空 body 的 HTTP 302，
> 重试一次就会成功——这是上游抖动，不是 Galbox 的问题。

### 4.3 按名字手动搜索

代码里有 `SearchManuallyAsync`（按名称搜出全部候选，不设阈值），但**当前版本的刮削页面上没有
搜索框或按钮**——这个能力只能从代码调用，界面上点不到。请用 4.1 的方式刮削，或在设置里
让自动刮削处理。

## 5. 错误检测

1. 打开左侧导航 **错误报告**。
2. 页面会先列出数据库里所有**未解决**的问题记录（`ErrorReportPage.xaml.cs.OnPageLoaded`）。
3. 顶部两个按钮：
   * **刷新列表**：重新载入问题记录；
   * **重新检测全部游戏**：对库里每个游戏跑一遍检测。
4. 左侧选某个游戏时，也会立刻对该游戏跑一次检测。
5. 每条问题可以：
   * **标记已解决**；
   * **下载所需组件**（如果这条问题带官方下载地址，会用浏览器打开）；
   * **尝试自动修复**（仅对支持自动修复的问题类型有效）。

检测内容覆盖常见运行问题（中文路径、日语区域设置、DirectX / 解码器等，见
`src/Galbox.App/Services/ErrorCheckingService.cs`）。**没有任何发现是正常结果**，
页面会如实显示空列表，不代表检测失败。

## 6. 存档管理

### 6.1 存档位置是怎么找到的

`ISaveManagementService.DetectSaveLocationAsync` 先判断引擎类型，再按引擎探测存档目录。
不同引擎的探测规则不同，例如 Ren'Py 会去找
`%APPDATA%\<游戏名>` 或 `%APPDATA%\<游戏名>-<随机串>\saves\`，也会看游戏目录下的
`game\saves\`、`saves\`（`EngineSaveDetector.DetectRenpySaves`）。

> ⚠️ 对**部分引擎**（KiriKiri、RPG Maker），当找不到专用存档子目录时，探测结果可能退化为
> **游戏安装根目录本身**（`EngineSaveDetector.cs:452-454`、`645-648`）。对这类游戏执行
> 恢复/回滚会在这个目录整体操作，**动手前请先自己确认备份内容与目标目录**。

### 6.2 创建备份

方式一：**存档管理** 页

1. 左侧列表选一个游戏（列表右侧的数字是已有备份数）；搜索框可按名称过滤。
2. 中间输入框填**备份描述**（可留空，留空会自动生成时间戳描述）。
3. 点 **创建备份**。
4. 过程中会出现遮罩层，显示阶段文案（扫描存档文件 → 创建备份目录 → 复制文件 →
   完成 → 验证完整性 → 清理旧备份）与百分比。
5. 成功后提示"备份创建成功：<名称>"。

方式二：**游戏详情页 → 存档备份 → 创建备份**（同上，描述自动生成）。

如果一条存档文件都没检测到，会提示"创建备份失败。未检测到存档文件。"——这是真实结论，不是 bug。

### 6.3 恢复一个备份

在某个备份卡片上点 **恢复**。程序会：

1. 检查目标目录里的文件是否被游戏占用（占用会拒绝恢复）；
2. 检查磁盘空间；
3. 把当前存档复制到一个临时目录（这是回滚用的保险）；
4. 解压备份覆盖回去；
5. 做一次完整性校验；**校验不通过会把第 3 步的临时副本还原回去并返回失败**
   （`RestoreBackupAsync` + `RollbackRestoreAsync`）。

> 这一步的校验允许文件数 20%、总大小 10% 的偏差，因此它**不能证明逐字节一致**。
> 对进度极其在意的游戏，建议恢复后再进游戏确认一次。

### 6.4 快速切换（"我想回到某个节点继续玩"）

备份卡片上的 **快速切换** = **先备份当前存档**，再恢复你选中的那个备份
（`SaveManagementService.QuickSwitchSaveAsync`）。切换成功后页面会提示
"已快速切换到：<备份名>"，并且刚刚自动创建的那个备份会出现在列表最前面。

> 已知缺陷：如果"备份当前存档"这一步失败（返回 null），代码**仍然会继续执行恢复**。
> 也就是说目标备份会被还原，但"切换前状态"没有被保护下来。做重要切换前，
> 建议先手动点一次「创建备份」。

### 6.5 删除备份与自动备份开关

* 备份卡片右侧的垃圾桶按钮：**删除该备份**（同时删除磁盘上的 ZIP 与数据库记录）。
* 页面右上角 **自动备份：开/关** 开关：**当前没有实际效果**。它只修改内存里的一个标志位，
  而自动备份的触发点（`CreateAutoBackupAsync`）在整个项目里没有任何调用者；
  重启程序后开关也会回到默认的"开"。要保护进度，请手动创建备份。

## 7. 设置页

设置页里**确实生效**的部分：

| 分组 | 生效的设置 |
|---|---|
| 数据源 / 刮削 | 四个源开关、匹配阈值、源优先级、添加游戏后自动刮削 |
| 老板键 | 开关、修饰键（Alt/Ctrl/Shift/Win）+ 主键、最小化到托盘、显示提示 —— 保存后会即时应用到进程监控服务 |
| 截图 | 截图目录、退出时自动截图、格式（PNG/JPG）、JPG 质量 |
| 高级监控 | 监控开关与轮询间隔 |

**目前只存不生效**的部分（能改、能保存、但没有代码读取）：

* 自动备份（退出时）、自定义备份路径；
* 启动时自动扫描游戏目录、扫描目录列表；
* 库默认视图（网格/表格）——库页面自己有视图切换按钮；
* 主题（浅色/深色）与语言；
* **Bangumi 访问令牌**：它能保存，`BangumiAuthService` 也会在启动时初始化，但刮削链路
  并不使用它（`GameScrapingService` 只依赖四个 API 客户端，`BangumiHttpClient` 也没有加认证头）。
  换句话说，**不填令牌一样能刮削**，填了也不会因此多出需要登录的功能。

### 老板键与截图是怎么工作的

应用启动时会遍历游戏库，把每个游戏注册进进程监控服务并启动监控
（`App.xaml.cs` → `ProcessMonitorStartup.RegisterLibraryAndStartupAsync`）。
之后：

* 游戏进程一起动就能识别为"正在游玩"；
* 按老板键隐藏游戏窗口，再按一次恢复；
* 游戏退出时（若设置里开了）自动截图到截图目录；
* 本次会话时长会累加进游戏的"游玩时间"。

判断是否真的在工作，看 **主页/详情页的游玩统计** 是否变化，或看
`%LocalAppData%\Galbox\logs\startup-YYYYMMDD.log` 里的这一行：

```
Process monitor: started=True, registered=N/M
```

### 截图：文件会生成，但详情页看不到

打开"退出时自动截图"后，游戏退出时确实会在截图目录（默认
`%LocalAppData%\Galbox\Screenshots\`）里生成 PNG/JPG 文件——**你可以直接去那个目录拿图**。

但游戏详情页的"截图"区域读的是**数据库里的截图记录**，而当前版本的截图链路
（`ProcessMonitorService` 的 `ScreenshotCaptured` 事件）没有任何订阅者，
**没有任何代码把截图写进数据库**。所以那一区会一直显示为空；界面上也**没有"手动截图"按钮**
（`CaptureFocusedWindowScreenshotAsync` 同样没有调用者）。

## 8. 补丁中心（当前的真实状态）

打开左侧导航 **补丁中心**，你会看到两块内容：

1. 上面是游戏列表与所选游戏在数据库里的"可用补丁"记录（右下角按类型过滤；
   每条只能点「详情」看信息）。**它仍然是只读的**：如果这个游戏没有记录，
   右侧显示 **"暂无可用补丁"**，并说明"尚未配置在线补丁源，本地也还没有这个游戏的补丁记录"。
2. 下面是**「本地补丁包（已下载）」**——这是补丁中心真正能干活的地方：

* **选一个你已经下载到本机的补丁压缩包**；
* Galbox 先把它解压到临时沙箱，列出**每个文件会落到哪里**，并把结果分成
  **覆盖（会先备份）/ 新增 / 冲突（来历不明，必须你逐个确认）/ 内容已相同 / 已拒绝**五类；
* 你确认之后才写入游戏目录，覆盖前先备份；
* 安装带进度、可以取消；装完给你**逐文件结果**，并可以在「状态台账」里看到这次安装的依据；
* 装错了点**「回滚」**，会把被覆盖的文件按安装前记录的哈希逐个还原（可以**逐字节**比对）；
* 如果上次安装中途断电/被杀，页面会提示**「检测到上次安装中断」**并给出恢复方案。

**仍然不做的事**：Galbox **不下载补丁包本身**。上游补丁源（moyu / NextMoe 那条线）
没有提供官方直链下载契约，所以程序化下载既不实现也不打算实现——它能做的是
**把你的浏览器打开到补丁页**，由你自己下载；下完之后回到上面第 2 步安装。
（moyu 在线源的服务层已经在仓库里了，但**界面接线还没接上**，所以你现在看不到它；
在那之前补丁中心不会假装能在线下载。）
之前那两个"下载/安装"按钮**已被删除**：它们只是睡一会儿再改一下数据库状态列，
既不下载也不安装。留着它们比没有更糟。

想验证这段引擎现在到底能不能用，可以运行它自带的取证工具（见开发者指南第 6 节）。

## 9. 还没有界面的功能

以下能力**在当前版本里用户点不到**（这份清单已经按代码重核过一遍）：

| 功能 | 现状 |
|---|---|
| **按名字手动搜索元数据** | 代码里有 `SearchManuallyAsync`（`ScrapingProgressViewModel.cs:342`），但刮削页只绑定了取消/应用候选几个命令，**没有搜索框**，所以界面上点不到 |
| **流程图追踪 / 社区成就** | **按规格只做预留**：接口、数据模型与功能开关都在仓库里，但两个开关是编译期 `false`，前端没有任何入口，也没有实现（详见下条说明） |
| **在线补丁源（moyu）的界面** | 服务层已实现并验收，**界面接线还没接上**；在那之前补丁中心只处理你本地已下载的包（见第 8 节） |

**下面这些以前在这张表里，现在已经有界面入口了**，所以从这份清单里移除：

* **存档节点 / 时间线 / 快照 / 剧情进度 / CG 解锁率**：去 **存档管理** 页点「扫描存档」，
  下面就会出现时间线、CG 图鉴与剧情进度，还能给某个节点打快照。
* **补丁安装（本机安装器）**：见第 8 节的「本地补丁包（已下载）」。
* **删除游戏 / 安装目录丢失检测 / 封面图下载**：都已合并进当前分支
  （删游戏只删记录、不动磁盘上的游戏文件；目录丢了会在库里标出来并阻止启动；封面会真的下载到本地）。

关于预留的两项，说明一下为什么"看不到"才是对的：产品规格对它们的原文是
**"第一版只预留接口，前端隐藏"**。所以仓库里**故意**没有入口、没有实现、也没有假实现，
只有接口与数据模型，验收检查 A90/A91/A92 就是在断言这一点。
它们需要自建服务端，第一版不联网做这件事。

## 10. 排障

| 现象 | 先查什么 |
|---|---|
| 双击没反应、没有窗口 | `%LocalAppData%\Galbox\logs\startup-YYYYMMDD.log`；正常启动会写入 `OnLaunched: startup sequence completed`，失败会写入 `EXCEPTION in OnLaunched` |
| 刮削一条结果都没有 | 刮削页的**数据源诊断**栏：能区分"上游报错"与"确实没有这个游戏"；也可能是该名字的缓存为空但网络不通 |
| 封面全是空白 | 封面会在刮削后由 `GameImageService` 下载到 `%LocalAppData%\Galbox\Covers\`（背景图与角色图分别是 `Backgrounds\`、`Characters\`）。先确认刮削确实命中了条目（详情页能看到评分/原名），再看网络能否访问封面 CDN；下载失败的条目会保留 URL，重刮一次即可 |
| 老板键没反应 | 设置里老板键是否为开、快捷键是否被别的程序占用；再看启动日志里的 `Process monitor: started=True, registered=N/M` |
| 想看数据库里到底有什么 | `%LocalAppData%\Galbox\galbox.db`（SQLite）。**改动前请先复制一份** |
| 想重置一切 | 关闭程序后删掉/改名 `%LocalAppData%\Galbox` 目录（会丢掉游戏库、备份记录与设置；`SaveBackups` 里的 ZIP 也会一起没，请先单独备份） |
